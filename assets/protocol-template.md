### 这个循环怎样工作

本任务由互不共享记忆的会话交替完成：立项写设计，评审判断设计与推进方式，工作轮实现，验收轮独立复验；会话之间只通过本文件与下列流程文件交接。循环无人值守：用户的决定在生成时写入 Task，终止时交回用户。

本文件分四类内容：**固定约束**任何角色都不放宽；**交接与账目**是会话之间的接口，连同「设计文档要求」「评审条件」与各任务段的步骤，按原文执行（步骤引用的做法按「方法与经验」处理）；**概念**是判断用的定义，按原文适用，后面的理由用来理解它；**方法与经验**写目的与做法，有失败记录的附例与迹象（没有起作用时的表现）。做法是建议，另一种做法更能达到同一目的时可以改用（固定约束 2）；写明为「标准」的部分按原文适用。例后括号写证据强度（多运行指两个以上循环，单运行指一个）与本 skill 维护记录 `assets/README.md` 的日期，供维护者查证。

### 固定约束

1. **核心目标与质量不变。** 核心目标的结果与质量标准（错误定义、应覆盖对象、残余容忍）、标「承重：核心目标 n」的编号要求、用户明确的范围、权限、资源约束与硬预算、项目权威规则，任何角色都不放宽：它们是用户与项目的决定，循环内没有人能改。证明方法、附加完成条件、决定、风险、进度量、估算与圈计划可依据证据修正（评审修正方案、证明方法、计划与估算；验收在本圈换量、确认契约定义缺陷，并按概念 4 取舍编号要求的证明方法），其中本身是用户或项目明确要求的仍按要求处理。修正不得靠删去应覆盖的对象、放宽残余、扩大信任基或隐藏失败取得通过；信任基只能在 Task 允许的范围内收窄。
2. **判断不由被判断的角色做。** 评判自己的成果或自己提出的方法时会偏向方便的结论，这与能力无关（单运行：skeleton-copy 的复评评判其它角色的方法时三次发现问题，评判自己的方法时三次都没有，11-02）。因此：四个角色在独立会话中完成；作者（立项、工作轮）不判定自己的成果完成；验收不信任工作轮的结论，自己取得进度数字；验收与评审写要达成什么，不替作者设计实现；提出证明方法的角色先用实验证明它；作出继续判断的角色写下下一圈可二元判定的预期与预计投入；偏离「方法与经验」中某项做法时，在运行记录写明目的怎样仍被满足。这些由下一个独立判定者先核对（验收轮第 1 步，评审两种进入方式的第 1、2 步）：作者不满足目的的偏离按未完成处理，判定者的由验收提请复评或由评审改判。
3. **未知不冒充通过，失败不被隐藏。** 判定器识别不了的成员判未知并失败；原因未查明的失败在取得基线证据前按阻塞处理（评审按「复评与停止」结束调查的历史失败除外）；无法判断是否阻塞时按阻塞处理；受验证错误影响的通过结论须重新验证。理由：一个虚假的通过会让之后各圈都建在错误上。
4. **用户的决定不由循环代做。** 价值判断（残余容忍、抽样策略、付费上限、范围判定、降级分支）只来自 Task。未规定的事项依据任务目标、项目原则与证据决定并记录理由，不要求用户选择下一步。不扩大授权、不提高硬预算，执行会突破硬预算的工作前停止尝试并记录已用量。继续确实需要改变用户目标、质量、授权或硬约束时停止尝试，写明约束、证据与建议交负责人；普通未完成项不是这样的理由。
5. **产品结果优先。** 流程文件服务于交付。记录写结论、证据位置与下一步；不为证明没有改动什么而计算哈希、封存清单或复述未变化的状态与计数（多运行：记账与过程自证曾占运行记录的 16%–24%，10-25）。
6. **各会话使用本文件**，不自行同步其它版本；用户明确要求迁移时，保存旧任务、状态与证据，记录修订范围，从指定恢复点继续。

### 交接与账目

#### 文件

本次运行只要求以下流程文件：

- 设计文档：`{{DOC_DIR}}/{{SLUG}}.md`
- 评审账本：`{{DOC_DIR}}/{{SLUG}}-review.md`，跨轮追加，不覆盖。
- 验收记录：`{{DOC_DIR}}/{{SLUG}}-acceptance.md`，每圈覆盖，保留四个常设段落（见验收轮）。
- 运行记录：`{{DOC_DIR}}/retro.md`，每轮追加一条（见「运行记录」）。
- 证据目录：`{{DOC_DIR}}/evidence/`。runner 写的快照在 `evidence/snapshots/<标签>/`（立项 `design-d<d>`，再入 `design-r<n>`，复评 `review-c<c>`，工作轮修订决定 `work-c<c>`），立项与各轮的实验输出放在 `evidence/d<d>/`，每圈的运行输出在 `evidence/cycle-<c>/`；不要把实验输出放进 `snapshots/`。
- 可执行参考：`{{DOC_DIR}}/reference/`。

#### 状态头与 runner

设计文档开头维护状态头，字段与取值固定，各会话与项目工具按原样读取：

```text
status: 立项中 | 实现中 | 已完成 | 停止尝试 | 不可实现 | 协议失败
design-round: d/3
cycle: c/C
current-milestone: M-xx
milestones: <已完成数>/<总数>
risks: <已退休数>/<总数>
progress: <进度量名>(<down|up>): v0, v1, ...
reentries: n
next-step: <验收轮或评审接受的下一步；立项通过时由评审轮写 M-01 的第一步>
```

账目由 `{{RUNNER}}` 维护，不手改数字（手算会出错，也可能改写历史）；runner 只记录事实，不判断进展，也不触发任何动作：

```bash
node {{RUNNER}} {{DOC_DIR}} state set <key> <value>      # 改一个状态头字段
node {{RUNNER}} {{DOC_DIR}} snapshot design-d<d>         # 改写设计前存快照
node {{RUNNER}} {{DOC_DIR}} diff design-d<d-1>           # 上一快照与当前设计的差异
node {{RUNNER}} {{DOC_DIR}} ledger add <id> <类别> <攻击对象> <后果或内容>
node {{RUNNER}} {{DOC_DIR}} ledger set <id> <open|closed|rebutted|note> [说明]
node {{RUNNER}} {{DOC_DIR}} progress append <value>      # 记录本圈实测值
node {{RUNNER}} {{DOC_DIR}} progress redefine "<量名>(<down|up>)" <value>  # 换量：里程碑切换、口径修正或判定器建成；旧序列保留在 || 之前
node {{RUNNER}} {{DOC_DIR}} cycle advance                # c 加一
```

脚本不可用时，手工完成同样的更新并在 `retro.md` 记一行原因。

- `d` 由评审在结论为「需要修订」时增加。首次立项第三次修订仍未通过时以 `协议失败` 交回用户：这时还没有工作成果可供判断，作者与评审可能在定义不清的任务上反复往返。这是本文件唯一的计数终止（多运行：设计 10 轮以上的 11 个循环只有 3 个完成，10-18）。
- `c` 由验收轮在一圈结束时增加；运行期复评作出结论也计一圈，再设计不另加。
- `C` 是预计总圈数，由立项给出、独立评审依据实测修正并保留旧值；不是硬预算，到达它不触发动作（「估算」）。
- `progress` 记录进度量的实测序列；换量用 `progress redefine`，旧序列保留，不跨口径比较（「进度量」）。
- `next-step` 是下一圈工作的唯一权威；验收记录的「下一步要达成的结果」是它的展开。

里程碑状态只有：`开放`（尚未完成）、`待审`（工作轮已取得通过证据，等待验收）、`已完成`（验收轮独立复验通过）。

#### 资源等待不结束轮次

目的：因资源暂不可用而结束一轮，下一个角色没有可判断的东西，还消耗一圈（多运行，10-16）。

本节适用于所有阶段，先于计数、结束和启动下一 session 的步骤执行，最后一圈也不例外。执行资源只指测试与运行资源及其排队入口；上游依赖未发布、权限未批不是资源等待，是风险清单的条目，按其分支处理。本轮必需验证（本轮按工作轮或验收轮规定要运行的验收命令与契约运行）因执行资源暂不可用而未运行或中断时，必须在当前 session 内使用等待工具等待，资源可用后继续执行；不得因等待结束 session、增加 `d` 或 `c`、启动下一 session，或判定任务失败。

优先使用项目已有的排队机制，遵守资源准入规则。等待工具单次返回或排队命令超时不代表等待结束：检查原进程，仍在排队或运行则继续等待，已因排队超时退出则在同一 session 重新排队，避免重复启动。没有排队入口时，用等待工具分段等待并复查准入条件。资源恢复后复核代码与环境，补跑缺失或已失效的验证；实际执行后发现的失败按原缺陷协议处理。本任务自己的运行环境（例如本工作区的栈）停止时，按项目规则恢复它是本轮工作，不是等待。

用户明确停止或宿主强制中断时，在已有 `retro.md` 保存当前轮、已完成工作、等待资源、进程与待执行命令，不自动交接；恢复后核对状态并继续同一轮。等待仍受用户明确的硬预算约束，耗尽时按概念 7 停止尝试；不得自设等待时限作为中断理由。已证实的其它技术或权限问题按「复评与停止」处理。

#### 运行记录

目的：下一个角色据此核对上一轮的判断，复评据此判断以往判断是否可靠。每轮在 `retro.md` 追加一条，只写：轮次与角色；结论；对上一轮预期的逐条核对（命中、未命中或无法判断，及证据位置）；本轮写下的预期与预计投入；偏离某项做法时目的怎样仍被满足；证据位置；下一步。不复述未改变的状态、计数与历史；交接只记录新会话的标识与读回的参数。

任务终止时补充总结，只记可核对事实：终止状态与原因；立项轮数、圈数与各里程碑最终状态；预期核对的命中情况；账本中阻塞问题、注意事项、驳回与转换为风险的数量；再入次数与原因；实现缺陷与验证缺口数、逃逸类别分布、各「机制·模块」与完成的结构性修改；进度量完整序列；主干既有缺陷及登记；对编号要求的全部取舍、理由与证据位置；人工介入次数（正常为 0）；对协议的改进建议（最多三项，附证据）。

#### 缺陷卡片

目的：弄清缺陷为什么没被验证发现，修验证机制而不只修这一个实例；卡片让复现能按「机制·模块」比对。每个实现缺陷在验收记录中写一张卡片：现象、证据、根因机制（取词表）与模块（项目的规范模块根，副本跨模块时写「跨模块」）、能否在任务基线上复现、逃逸证明、逃逸类别、同类普查、补救、阻塞判断与依据；保留当前里程碑的全部卡片。项目画像有「缺陷复盘协议」时用画像的词表与工具。逃逸证明：在修复前的代码上运行工作轮声称通过的验收命令与最近的既有测试，记录是未执行、看不到失败、失败被忽略，还是没有相关测试。逃逸类别与补救：

- **A 验证体系缺陷**（验证未执行、被跳过、看不到失败，替身或夹具与真实实现不一致，判定器定义缺部分）：修复验证机制本身，不只增加一个用例。
- **B 用例不足**（机制正常，缺维度或实例）：以判定器列出全部同类实例，扩展模型、参考函数或输入生成器；没有可用模型时才补单个用例。
- **C 其他**（设计未定义该行为、缺陷在第三方或框架）：写明需要的再入或上游修复。

### 概念

1. **主张的三种性质。** **决定**（方案、事实归属、顺序、接口、取舍）靠论证加同一轮的最小验证实验确立，实验运行真实代码路径（导入生产函数、使用生产 schema 或在真实环境中执行），手工转写源码逻辑的模型不算，也不以负载或时长推迟；**全称性质**（全部、每个、任一）靠契约中的判定器在真实人口上运行确立；**语义性质**（只能靠判断的类别，例如注释与文档中的陈述）靠 Task 声明的固定人口、抽样策略与通过标准确立。为什么：决定错了在实现中返工，全称主张举例再多也不成立，语义主张没有约定的抽样就审不完。每种用足够的最便宜证据。
2. **判定器。** 三部分：**人口**从结构性权威派生（类型、符号引用、注册表、生成物、文件全集、语法树节点种类全集），在契约中命名，不以本任务改动的文件为人口；**归类带未知分支**，不能识别或需要判断而未判断的成员判未知并失败；**信任基**写明接受而不证明的前提，只允许平台有文档的语义和仓库中已在运行的门禁。手写清单、选定模式检索、选定探针与阅读审阅都不是判定器。为什么：全称主张的漏洞几乎都出在检查范围比主张窄而漏掉的成员不报失败；结构性权威使范围不由检查者挑选，未知分支使漏掉的显式失败，信任基写明未证明的前提。缺三部分之一是契约定义缺陷，修正是补全定义并重跑人口，不是补列成员或写法（多运行，10-13）。固定的是应覆盖对象的定义与权威来源，不是某次枚举的行号；成员移动、替换或退出须保留来源与行为证据并经独立复核，既不因旧坐标失效永久增加未知，也不因当前漏枚举就撤销覆盖。「本任务改动或要求处理的对象的全部内容（按文件、模块或记录整体计）」只作语义性质的成员集合。
3. **返工检验。** 主张在实现期被证伪会导致重做已完成里程碑、改变方案或跨里程碑接口、执行或撤销不可逆操作、或突破用户明确的硬约束时，才必须在立项期关闭；其余由所在里程碑的验收发现。立项期答不了的量写成风险：该量、依赖它的决定、每种结果预先决定的分支，排进最早的里程碑。为什么：立项期检查越多，交付开始越晚（多运行：165 个采纳的阻塞问题中推迟会返工的只有 5 个，10-17）。
4. **核心目标与编号要求。** 核心目标是任务存在的理由，任一条不成立即任务失败。编号要求描述范围与验收约束；其中的结果、质量与明确约束按固定约束 1 处理，证明方法与附加要求可依据证据取舍，不要求先证明原文不可达：验收可在本圈取舍并写入验收记录，影响整体方案、验收方法或工作组织的交评审，由评审把取舍后的口径、理由与证据位置写入设计中该要求下；非核心要求不可达时按 Task 的降级分支。为什么：每条编号要求都不可取舍时，一条非核心要求的不可达会拖住整个任务（多运行，10-12）。
5. **实现缺陷与验证缺口。** 实现缺陷：要求交付的产品能力或对象不符合设计中有效的要求或 Task。验证缺口：验收方法、辅助检查器、可执行参考或证据不足以支持结论（漏检、误报、出错）；它们本身是 Task 要求交付的对象时，其错误是实现缺陷。为什么：两者补救不同，混淆会让产品承担不需要的结构义务，或放过真实错误（多运行，10-23）。
6. **阻塞问题**（评审立项时用）。须同时写明攻击的对象（某条 `D-n`、某份契约的字段、某条 `R-n`、某条编号要求的确立方式、某个里程碑的划分或顺序）和后果（返工检验的四种返工之一；某条核心目标不可达；与 Task 明文约束或项目权威规则冲突；或关键技术主张没有验证或验证不真实：没有运行真实代码路径、没有覆盖该主张、结果不支持结论）。缺一项的是注意事项，记入账本（`note`），不阻塞，不写入设计。不是阻塞问题的：判定器定义完整时某个成员未列出或某种信任基之外的写法；契约运行中的失败与未知；已写明理由的取舍与范围判定（有理由不成立的新证据才重开）；未改动且已有结论的决定。为什么：没有对象与后果的意见无法修正也无法反驳，立项会无限往返（多运行，10-12、10-17）。
7. **继续、停止尝试、不可实现与协议失败。** 继续：存在有依据、值得执行的下一步。停止尝试：找不到这样的下一步，或硬预算已耗尽；不等于不可实现。不可实现：有目标层面的证据（真实实验揭示无法绕开的限制，或准确引用加反例证明约束矛盾）证明某条核心目标在明确约束下不可达；实现失败、估算被超过、进度量不动、再入多次都不够。协议失败：首次立项修订三次仍未通过，交回用户澄清任务定义，不据此声称不可达。为什么：把「这次没做成」写成「做不到」会让用户放弃可达的目标（多运行：计数规则曾把 1542 c13、1670 c9 判为不可实现，复盘未证明不可达，10-20）。
8. **阻塞的缺陷。** 验收对每个缺陷与失败判断是否阻塞当前里程碑，在卡片写明依据，下一圈验收与评审可复核改判。**阻塞（范围内）**，满足任一项：使核心目标、Task 编号要求（按经取舍的口径）或当前里程碑某条结果不成立，或所在内容正是它们要求创建、修改或修复的对象；由本任务的改动造成（任务基线上不能复现）；位于本任务为当前里程碑新建或修改的产品内容中。只被阅读、报告或提及的对象、验收命令本身，以及为修复、登记或检查范围外缺陷所做的改动，都不使对象进入范围。**不阻塞（范围外）**：写出核对过的要求句子与不符的理由，按项目画像的缺陷复盘协议登记（缺陷条目、仍失败检查的 owner 与期限、后续 issue），不成为完成条件；登记不等于机制闭合。**分配**：阻塞的缺陷默认是当前里程碑的完成条件，结果依赖它或评审确认时可分配给后续里程碑或独立 issue；已完成的里程碑不重新打开，归属于它的缺陷归当前里程碑。在任务基线上能复现的缺陷，阻塞的在本任务修复，都按画像的协议登记（无规定时在 `retro.md` 列出）。结构性修改需要 Task 排除的改动时写明需要的再入或上游修复；该缺陷违反 Task 要求或里程碑验收时，里程碑仍不能关闭。**原因未定位的失败**：在不含本任务改动的基线检出上（优先当前主干；本任务批次已合入或主干无法运行时用任务基线 revision）以同一机器与配置执行同一检查，本任务新建的检查叠加执行；出现一次（含间歇）即判不阻塞并登记，执行次数达到分支上的次数仍不出现或尚无基线结果时按阻塞处理（评审按「复评与停止」结束调查的历史失败除外）。合入本任务提交的分支、代码阅读、`git blame` 与单独重跑通过都不是基线运行或环境证据；环境失败须有证据（同一完整命令在证明空闲的机器上通过，或错误直接指向机器或外部服务），取得环境正常的结果前对应验收视为未执行；只在负载或特定交错下出现的竞态是代码缺陷。Task 另有规定时以 Task 为准。为什么：不把任务外的问题拖进任务，不把任务造成的问题推出去，不把原因未知的失败当作环境问题放过；但原因未明的历史失败也不应永久绑定为完成条件（单运行：1670 c15，10-20）。

### 方法与经验

#### 取证

**最小验证实验。** 目的：判断要能被下一个角色复核；关键技术主张错了会在实现期返工，同一轮用实验检验更便宜。做法：判断优先用源码、现有测试、实际命令或实验，纯逻辑矛盾可用准确引用加具体反例证明。属于立项期义务的主张（例如接口或注入路径是否存在、迁移能否执行、判定器能否在真实人口上运行），由写入它的会话同一轮按概念 1 用实验证明并引用输出；无法执行时不写入设计。迹象：写进设计的主张下一圈被证伪。

**引入或改写证明方法时，先证明它能拒绝要拒绝的失败。** 目的：判定器能拒绝失败，它的通过才有意义（语义审阅者也是判定器）；提出方法的角色最难看出自己方法的漏洞。做法：写进设计前在真实代码路径上运行，负例优先用历史缺陷卡片，在每一条通过路径上各试一次。核心目标本身陈述判别力时（例如「删去任一接线合同变红」）做全量资格化：变异算子集从权威来源派生并统计检出比例，自选注入不能代替；其它契约做一次正向与一次负向对照。核对声明的检查要核对声明与代码一致，不只核对格式。例：skeleton-copy 复评 c12 引入「读差异的非撰写者复核」而没有实验，下一圈复核者复述了撰写者的错误归因；复评 c16 新增的通过写法只用历史卡片测了另一种写法，复评 c18 发现它接受 24 张中的 8 张；163 个通过格式检查的 `deleted` 声明中 99 个引用保留代码（单运行，11-02）。迹象：同一判定器的定义每次复评都被改写。

**全称主张的确立时机。** 目的：立项不必建完判定器，但要证明它能在真实人口上运行并知道成本。做法：立项期只要求定义与一次真实切片上的计数和单位成本，归零是实现期的工作；违反会阻塞的全称编号要求同样写明确立方式（判定器，或 Task 中的人口与抽样策略）。例：1542 v2 的判定器每轮被重定义，进度不可测（多运行，10-18）；skeleton-copy 的一条全称编号要求以逐行阅读确立，三圈连续发现同类缺陷，之后用三次复评补建判定器（单运行，11-02）。迹象：同类缺陷每圈由验收发现，工作轮没有可运行的检查。

#### 组织

**竖切。** 目的：尽早在真实路径上取得计数，暴露不能渐进完成的主张。做法：每个里程碑是可运行、可验收的系统状态；第一个里程碑消除最高的风险（清单为空时只要求竖切），在一个真实切片（一个变体、一个槽位、一个入口）上端到端跑通，即产品路径真实运行、核心目标契约给出通过与失败的计数；先竖切再扩人口，不接受先横向建完一层的计划。例：高 reopen 的里程碑都在循环末尾、产品型里程碑关闭之后（多运行，10-18）。迹象：前几个里程碑关闭后，核心目标契约仍没有在真实路径上运行过。

**同类一次处理。** 目的：一个根因只花一圈。做法：问题写明根因与检查范围，范围内全部同类由判定器列出并一次处理；同类按被违反的规则认定，不按写法或位置；只在作用范围内认定。例：慢里程碑中审计当轮新增检查才发现的缺陷占 25.4%，快里程碑 10.6%（多运行，10-13）。迹象：连续几圈的卡片违反同一条规则，只是位置不同。

**单一陈述与可执行参考。** 目的：一个事实写在两处就会分歧；文字写的精确规则会成为下一轮的攻击对象，可执行的参考能被运行。做法：设计只陈述当前结论，每个决定、事实或规则只在一处陈述；过程写入 `retro.md`，实验输出放 `evidence/`，再设计时改写对应段落而不在原文后追加说明，被替代的内容留在快照中。精确行为（分类、取值表、逐条规则、真值表）交给 `reference/` 下的可执行参考（原型函数及判别用例集，或最小契约测试）作为唯一权威。例：10 个高轮次循环在领域第二次出问题时补表格，之后该领域继续出问题（多运行，10-12）。迹象：阻塞问题落在上一轮写入设计的文字规则上。

**设计范围与转换为风险。** 目的：立项既不因范围扩大而无法通过，也不搁置解决不了的问题。做法：范围以 Task 的编号要求和明文约束为界，修正范围内对象的事实错误、矛盾、可执行性与可验证性不算扩大；新对象只在缺少它会使某条要求的验收条件或目的不能达成（写明编号与失败方式），或范围内对象改为判定器人口时纳入；范围外发现记入账本（`out-of-scope`）并按概念 8 登记，不写入设计。分析解决不了的阻塞问题转为写明里程碑、分支与触发条件的风险后闭合；属于立项期义务的问题不得转换。迹象：每轮评审都提出新的范围外对象。

#### 进度与估算

**进度量。** 目的：让当前里程碑剩余的工作可见，作为判断的依据；它不是目标，涨落不触发动作。做法：选随剩余工作变化的量，判定器建成后以首次计数换量，新口径须有实测初值。量反映不了的完成条件在里程碑下逐条列出、验收逐圈核对；它们占剩余工作的主要部分，或量已到终点仍有工作、新增条件不在量内、工作推进而量不动时，换量。不以重算口径制造进度。例：1496 v3 的量冻结在媒体裁定数，实际工作在不进量的结构条件上（单运行，10-25）；skeleton-copy 复评 c14 保留值为 8 的量，把剩余的 1,557 个成员写成量反映不了的条件（单运行，11-02）。迹象：量接近终点，估算的剩余圈数却不减少。

**估算。** 目的：给判断进展一个参照。做法：以一圈实际处理的成员数（成员得到最终结论：修复后通过或作出记录的裁定；扫描不是处理）与测得的单位成本估算，资格化与逃逸普查分别计入，写明假设与下一次核对点；估算被实测推翻时由评审修正方法或计划，不以旧估算为理由删减要求。复评时对照历次的 `C` 与里程碑预计结束圈。例：1670 v3 以立项只处理的 5 个成员作分母算出 `C` = 895（单运行，10-19）；skeleton-copy 的 M-04 在四次复评中预计在第 15、17、19、22 圈结束，每次写剩余约 3 圈（单运行，11-02）。迹象：每次复评写下的剩余圈数不减少。

**可核对的预期。** 目的：检验上一次判断是否可靠，据此决定能多依赖以往的判断。做法：作出继续判断的角色写一到三条可二元判定的预期与预计投入，下一个独立角色先逐条判命中、未命中或无法判断。读历次核对时，把推进剩余工作的预期与门禁类预期分开看；用时低于预计而主要预期未命中，不算投入预计准确。例：1542 c117 写下二元检查点，c119 由另一会话核对未达成并撤销失效的方法（单运行，10-25）；skeleton-copy 汇总 36 条预期中 28 条命中，推进剩余工作的那一条连续 3 次未命中（单运行，11-02）。迹象：预期无法判断，或核对总是命中而进度不前。

**交给验收前先自查。** 目的：自己能发现的缺陷不留给验收，否则晚一圈才被发现，还多一次全量验证。做法：每次交给验收前（不只是标 `待审` 时），用不由自己挑选的输入检验本轮成果，例如从契约的人口权威派生、不在本轮改动目录内的变体（删去成员、加回第二路径、改写缺省），或以往卡片中的缺陷形态；应失败时失败，还原后通过；发现的缺陷本轮修复。例：1670 v3 的 M-01 六次退回都由验收用这样的变体发现（单运行，10-19）；skeleton-copy 的这一步只写在「标 `待审` 前」，M-04 的工作轮从未申请 `待审`，缺陷都由验收晚一圈发现（单运行，11-02）。迹象：验收发现的缺陷，用同类变体本可在工作轮内发现。

**每一轮交出一个能被判断的成果。** 目的：验收和复评只能判断已经做出来的东西，一轮只做一小部分就把判断推迟一圈。做法：完成验收记录「下一步要达成的结果」再结束；提前结束时写明具体阻塞及其证据；用时低于预计、写给验收的复评条件都不是结束的理由。例：skeleton-copy 工作轮 13、15、17 分别用 1 小时 50 分、2 小时 6 分、1 小时 10 分就结束（预计 6–7、7–9、9–11 小时），主要预期未命中；工作轮 17 以写给验收的复评条件为停止理由（单运行，11-02）。迹象：用时明显低于预计，主要预期未命中。

#### 缺陷复盘

**复现与结构性修改。** 目的：同一机制反复出现说明原因在结构上，逐个修实例下一圈还会出现。做法：本圈卡片与当前里程碑既有卡片的「机制·模块」相同时，验收对其全部卡片做逃逸证明与同类普查，判断原因是否在结构上（同一事实有多个副本、写者或推导位置；缺少权威来源、类型化载体或统一的参考函数），写入卡片供复核。在结构上的，下一圈做出使该机制不能再发生的修改，作为当前里程碑的完成条件；结构由工作轮设计，并同步修订设计中对应的决定。标准：事实只剩一个写者和一个推导位置（比较副本是否一致的检查是验证补救，不算）；结构性质由判定器机检（类型、模块边界，或从权威来源列举全部写者与读者的契约测试），只识别已列出形式的检查不算；用一个从人口权威派生、不在工作轮目录内的变体核验，以第二条路径或未列出的写法加回时变红；逃逸类别要求的验证补救已完成。结构完成前，新实例照常是实现缺陷。语义类别的结构性修改是删去副本或改为引用权威，载体是记录或流程时是判定器新增一条有红对照的规则，验收按 Task 的抽样策略终止。例：按已列出形式检查时，识别器每轮扩展一种写法，审计在列举之外继续找到成员（多运行，10-13）；由计数自动产生的结构完成条件使里程碑无法收敛（单运行，10-25）。迹象：结构性修改完成后，同一机制仍以新写法出现。

#### 复评与停止

目的：进展停滞时由独立角色回到用户目标，判断推进方式出了什么问题、怎样继续最有价值，不让无效方法继续消耗圈数，也不在目标仍可达时放弃。

**何时复评。** 进展明显低于预期、上一圈预期未兑现且原因不在下一圈可修复的局部、反复返工、数值回落后仅恢复旧成果、方案被证伪、进度量失真或已到终点仍有范围内义务、同类失败反复出现、估算不再可信时，验收交给已有的独立评审者；仍有未完成项、局部计数改善或没有新缺陷本身不足以支持继续；首次完整成功或合格成本样本不是复评前提。例：验收等待首次完整成功才复核吞吐，六圈计数在 0、6、8 间往复（单运行：1542，10-21）。

**怎样复评。** 依据整个任务的实际执行、成果、失败和投入回答：**现在是否存在一个有依据、值得继续执行的下一步？** 先读历次预期的核对结果。重新考虑方案、工作组织、验收方法、附加要求、进度量和估算；历史方案、结论与继承义务都是证据，不预设仍然正确，判断不限于本次差异或当前里程碑，围绕造成停滞的关键约束与假设。分清已实际执行与仅被派发的动作：关键动作未执行时先诊断执行障碍。多次再入既不是自动停止也不是自动续跑的理由。例：复评只复核本次修正涉及的决定，已撤销方法的继承义务继续阻塞（多运行：1542、1496，10-23）；同一动作被重复派发而没有实际执行（单运行：1542，10-22）。

**继续时。** 说明当前方法为何仍有效或应修正什么，写明具体下一步、依据、可二元判定的预期（一到三条）与预计投入。上一次的预期没有兑现时，先说明原因及这次依据有何不同；不只增加圈数或重述待办，不以「做完一小批再复评」代替判断。成本不确定时如实保留不确定性；原因不清但有值得执行的最小判别实验时，它可以成为下一步。评审可直接修正计量、估算和计划，实质技术再设计交作者；只修改受新证据影响的部分。

**替换证明方法与附加要求。** 评审可撤销不必要的附加要求、替换失效的证明方式、调整里程碑归属，按它保障的结果与质量判断必要性，不以提出者、文档位置或历史触发次数决定。替换后仍须覆盖原对象、满足原残余容忍、能检出仍有效要求的缺陷，新方法先证明能拒绝要拒绝的失败；只检验已撤销方法或格式的旧对照可有据修改或撤销；取舍写入设计并保留旧结果及理由。原因未明、当前未再现的历史失败，可依据已有调查、当前验证与剩余风险结束调查、不再阻塞，保留失败事实与未知原因，不写成已修复。修正不要求先证明目标不可达或绝对无风险。

**停止与记录。** 找不到有依据且值得执行的下一步时停止尝试，保存成果、失败方法、剩余工作和恢复所需条件；只有目标层面的证据才判不可实现（概念 7）；超过 `C` 不是停止的理由。不另建裁决角色或轮询任务。

### 设计文档要求

设计文档是立项的产物，也是评审与各角色的共同依据；七部分各只陈述当前结论，保持一次能读完的篇幅。

1. **背景与基线**：与任务有关的事实及其证据；任务开始时的 Git revision、工作树状态与相关的已有测试结果。
2. **目标与完成定义**：逐项对应 Task 的核心目标与编号要求并写明怎样确立（核心目标指明验收契约；全称编号要求见「全称主张的确立时机」）；经取舍的要求写取舍后的口径、理由与证据位置。完成定义：全部核心目标的契约通过，全部风险退休，全部里程碑 `已完成`。
3. **决定登记**：只保留一个方案，编号 `D-01..D-n`，每条写结论、理由、证据位置、被否的替代方案和若它错了的返工后果；被驳回过的异议记一行结论，再次提出须有新证据。
4. **风险清单**：编号 `R-01..R-n`，每条写不确定的量、依赖它的决定和消除方式（本轮用实验退休，或放进最早合适的里程碑并写明怎样取得证据、结果怎样改变后续工作）；属于立项期义务的须在立项期退休。
5. **验收契约**：每条核心目标一份，使通过不由判定者临时决定。字段：人口的权威来源；信任基；未知即失败；残余容忍（从 Task 抄录）；资格化方式；一次真实切片上的运行：通过、失败、未知的计数及清单位置，单位成本，实际处理的成员数。切片在交付工作区的真实树上运行，含通过与失败或未知各至少一个成员，写明占人口的比例，进度量初值取其计数；单位成本由实际处理的样本测得（不少于 5 个取中位，人口不足时全查），不估计，处理数乘单位成本应与实际耗时大致相符。A 类契约是既有测试、旅程与门禁的命令清单及预期结果。C 类契约写固定人口、抽样策略、吞吐估算与裁定记录位置，切片指对不少于样本量的成员作出记录的裁定，通过指全部成员有记录的裁定且按 Task 的抽样策略与通过标准复核一次全样本后满足；模板不自定零错误。
6. **圈计划**：里程碑 `M-01..M-N` 按依赖顺序编号，每个写可观察的结果、覆盖的 Task 要求、前置里程碑、验收命令（尚不存在时写需要新增什么）、退休的风险、进度量、估算圈数及依据、量反映不了的完成条件；第一个里程碑是竖切片并退休最高风险。
7. **估算与硬预算**：`C` 按「估算」给出；用户明确给定的费用、时间或圈数限额单独列明来源和已用量，不随估算上调。

### 评审条件

目的：用设计产物的状态定义「可以开始实现」，不用评审是否还有意见定义（多运行：以评审沉默定义通过时，全称性质的任务不终止，10-18）。评审只审决定、风险、契约、编号要求的确立方式与圈计划，不审实现细节。**通过**的四个条件，全部满足即通过，与评审是否还有意见无关：

1. 设计中没有未反驳的阻塞问题（概念 6）。
2. 每条核心目标有验收契约，字段齐全，残余容忍与 Task「价值判断」一致；涉及全体对象且违反会阻塞的编号要求写明确立方式（判定器，或 Task 中的人口与抽样策略）。
3. 每份契约在真实切片上运行过一次，有计数与测得的单位成本；切片覆盖它声称验证的完整路径，不把局部裁定或扫描的吞吐当作完整验收的成本；未验证的部分列为风险，不要求立项期建完全部判定器或枚举全人口。圈数估算使用这些数字并标明假设，硬预算与估算分开。
4. 风险清单中每条风险有消除方式，按返工检验属于立项期义务的已退休；第一个里程碑是竖切片。

4. 判断复现：本圈卡片有与当前里程碑既有卡片相同的「机制·模块」时，按「复现与结构性修改」判断原因是否在结构上，结论写入卡片；在结构上的，把结构性修改写入完成条件；工作轮为结构性修改修订的决定一并核对。
