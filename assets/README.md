# 协议模板维护说明

`protocol-template.md` 是新生成循环任务的模板来源。每个任务文件都会包含生成时的模板全文和模板哈希；运行开始后不得同步其它版本。

## 当前设计

任务文件结构为：共享规范 → `Task 1` → `additional task 1` → `2` → `3` → `4`。每个任务末尾直白写明下一步启动谁；裁决与审计中的分支也写成按顺序命中的执行句，而不是需要模型推理的抽象循环协议。

当前模板保留：

- 可选的队列终止句：生成时写死 `{{ON_TERMINATE}}`，无队列则不启动新 chat，有队列则启动队列文档。
- 独立会话之间的设计、评审、实现和审计分工。
- 六类设计复审条件。
- 评审与裁决双方的同类问题完整检查责任。
- 里程碑顺序和独立审计关闭权。
- 每个里程碑的精简可执行验收。
- 验证缺口加强后立即复验的实现审计流程。
- 审计轮对下一实现轮给出明确工作指令。
- 设计 15 轮和实现 `5 × 初始里程碑数` 的预算。
- 里程碑 reopen 计数与 domain/milestone 收敛审计。

当前模板不再统一要求：

- 规范性条款和决策编号体系。
- 条款交互矩阵与覆盖轮转账本。
- 裁决索引和多份跨轮状态文件。
- 设计期通用断言库、证据 schema 和大规模负向夹具。
- 人工维护的测试白名单、隔离基线和设计确认。
- 单个里程碑预算、争议状态和人工续跑菜单。

## 维护要求

1. 使用多个任务的可核对复盘证据评估模板，不因单个任务增加全局规则。
2. 优先删除无助于产品推进的流程要求。
3. 新规则必须说明它防止的具体失败，并说明为何不能由项目原有测试或角色职责解决。
4. 模板使用正式、准确、容易理解的语言；任务接力必须直白可执行。
5. 修改模板后更新 Git 提交；任务文件中的模板哈希用于识别运行版本。

## 2026-07-31 重构

本次版本根据 mesh table、mesh elastic scaling 和 mesh scale switch wiring 多次运行的复盘进行重写。历史记录显示：

- 设计失败主要来自验证要求不断扩展、覆盖流程过重和协议版本中途变更。
- 最有效的机制是实际代码验证、同类问题一次检查、有限行为使用表或参考函数表达，以及实现审计加强验证后立即复验。
- 实现预算应在里程碑之间共享；切换类里程碑可能使用超过五轮，但完整任务仍可能在 `5 × 里程碑数` 内完成。

因此本版本把 skill 恢复为任务编排模板，项目特定的验证模型由具体任务按需要建立。

## 2026-08-04 循环写法回退

把任务之间如何接力的写法换回归档任务常用的顺序任务体：共享规范在前，`Task 1` / `additional task 1–4` 依次列出，每步末尾写清启动目标。六类复审、共享预算、reopen/收敛等新内容保留不动。

## 2026-08-24 队列终止接力

串行大任务不再使用独立监督 session 做定时轮询。循环任务在 additional task 2 与 additional task 4 的终止出口执行生成时写死的 `{{ON_TERMINATE}}`。有队列时启动队列文档；无队列时保持「终止，不启动新的 chat」。

## 2026-08-30 按任务指定会话后端与启动参数

启动句中的单一 `{{SESSION_SKILL}}` 按目标任务拆分为 `{{SESSION_SKILL_REVIEW}}` / `{{SESSION_SKILL_ADJUDICATE}}` / `{{SESSION_SKILL_IMPL}}` / `{{SESSION_SKILL_AUDIT}}`，并在每个启动出口增加 `{{SESSION_ARGS_*}}` 启动参数后缀（无参数时为空字符串；有参数时为「，启动参数：`<flags>`」）。设计评审与实现各有两处启动出口，同名占位符全局同值。队列终止句同样在生成时写死队列接力后端与参数。旧任务文件继续使用生成时的模板快照，不受影响。
